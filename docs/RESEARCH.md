## 2. “完美通关”定义与验收指标

- **完美通关**：在给定地图上无失败地吃满全部食物并覆盖全部可通行格。程序判定条件：`蛇长 == 可通行格数`（此时地图上不再可能生成食物）。
- **吃满率 fillRate** = (最终蛇长 − 初始长度 3) / (可通行格数 − 3)。通关 ⇔ fillRate = 100%。
- **格子覆盖率 coverage** = 蛇头到访过的不同可通行格数 / 可通行格数（允许重复经过）。
- **路径长度**：总步数与“步数/食物”（越小越高效）；**运行效率**：每步决策平均/最大耗时、超预算比例；**内存**：单步峰值搜索节点数与估算 KB（节点×24B + 栅格位图与邻接表）。
- **失败原因**分类：撞墙 / 撞自身 / 撞障碍 / 被困（无可行移动）/ 饥饿（连续 6N+100 步未进食，判定为死循环）/ 步数上限（2N²+1000）。

### 统一复现环境

| 要素 | 规则 |
| --- | --- |
| 随机数 | mulberry32；第 i 局 seed = 基础种子 + i；障碍流 = mix(seed,1)，食物流 = mix(seed,2)，回路生成树流 = seed |
| 初始蛇 | 尾 (0,0)、中 (1,0)、头 (2,0)，长度 3，与回路方向一致 |
| 单格障碍(cell) | 密度 d：目标数 = round(d·W·H)，按 RNG 逐格抽取；保护初始蛇周边一圈；拒绝规则：任一自由格自由邻居数 < 2（死胡同对无法倒退的蛇意味着必然覆盖失败）或自由区域不连通；最多尝试 20×目标数 |
| 宏格障碍(block) | 边长须为偶数；以 2×2 宏格为单位按 RNG 抽取，保护宏格 (0,0)(1,0)，拒绝使宏格图不连通的放置；数量 = round(d·宏格数) |
| 食物 | 在“非障碍、非蛇身、非食物”的格中按食物流 RNG 均匀抽取；同时保持 foodCount 个；有效期 TTL 步后消失并立即补生 |
| 计时 | performance.now() 包裹 decide()；预算：基础 5ms、中等 10ms、困难 16ms |

注意：食物位置依赖当前自由格集合，因此同一 seed 下不同策略看到的食物序列在分叉后会不同——这是所有随机食物贪吃蛇基准的固有性质；“可复现”指同一 (seed, 策略) 组合的结果逐位一致。

## 3. 算法选型：图搜索 vs 哈密顿回路

### 3.1 图搜索路线（BFS / A* / 最长路径 / 死路避免）

- **最短路径**：网格为单位代价图，BFS 即最优；A* 使用曼哈顿启发式 h（可采纳、一致），结果同为最短但扩展节点更少。本实现的 key 编码为 `f·1024 + h`，f 相同时优先 h 小者以更快收敛。实测 10×10 上贪心 A* 单步峰值节点≈134，安全 A*（多次搜索叠加）≈260。
- **最长路径**（借鉴 stevennl）：严格最长简单路径是 NP-hard；采用“BFS 最短路 → 反复在相邻两点同侧插入两个自由格 (a→c1→c2→b)”的多项式扩展法，得到尽量铺满空间的路径。用于**追尾**（拖延时间、维持连通）与**绕行吃食物**。
- **死路避免**三重保险：① **虚拟蛇**——沿候选路径模拟前进（含增长），到达后检查“新头能否到达新尾”，不能则拒绝；② **追尾**——沿最长路径走向蛇尾（尾巴总在移动，跟着尾巴永远不会被围死）；③ **洪水填充兜底**——选择可达空间最大且能看见尾巴的方向。
- **饥饿逃逸**（本方案新增）：追尾模式下蛇身会形成稳定环，被环包住的食物永远吃不到；每 N 步在“最长追尾/最短追尾”之间切换，改变蛇身排布。实测在单格障碍地图上把吃满率从 86.1% 提到 88.0%。

### 3.2 哈密顿回路路线（生成 / 遍历吃满 / 捷径）

- **生成 ①** 任一边为偶数：zigzag——第 0 行/列作回程通道，其余行/列蛇形往返，覆盖 W×H 全部格。
- **生成 ②** 奇×奇地图（如 15×15）：由二分图奇偶性可证不存在哈密顿回路（回路长度必为偶数）。本实现构造覆盖 W×H−1 格的回路并跳过角格 (0,H−1)，赋予它与 (1,H−2) 相同的**别名序号**：蛇经过 (1,H−1)→(0,H−2) 一段时可绕行经过角格，因此依然能吃到落在角格的食物并 100% 覆盖。
- **生成 ③** 带障碍（对齐 2×2 宏格、边长偶数）：**宏格生成树法**——在自由宏格图上用随机化 Prim 建生成树，每个宏格是一个 4 格小环，沿每条树边把两个小环“缝合”，树无环且连通 ⇒ 得到唯一覆盖全部自由格的回路。这是对哈密顿方案支持障碍的关键改造，也是中等 A/困难 A 100% 通关的基础。
- **遍历吃满**：设回路长 L，相对蛇尾的序号 rel(c) = (idx(c) − idx(tail)) mod L（尾格取 L）。纯回路策略每步走 rel = rel(head)+1 的格。由于回路覆盖全部自由格，蛇身只会占据回路上连续的一段，蛇头前方永远是自由格，直到蛇长 = L 即通关。
- **捷径规则**（借鉴 J. Tapsell / perfect-snakeAI，并给出证明）：候选邻格 n 允许作为捷径当且仅当 (a) rel(n) > rel(head)；(b) rel(n) ≤ rel(最近前方食物)（不越过食物）；(c) L − rel(n) ≥ 2 + 食物数（安全裕量）。

> **安全性证明（不撞墙、不撞身）**：不变量“所有蛇身格的 rel 位于 [0, rel(head)]”。初始成立；每次只向 rel 更大的格移动，新头的 rel 严格大于所有身体格；尾巴移动只会使区间左端右移；因此 rel > rel(head) 的格永远不是蛇身，而回路上的自然下一格恰好满足此条件且必与蛇头相邻（回路定义）。 回路不含墙/障碍，故永不撞墙。唯一需要额外处理的是“进入尾格”：只在不增长的步中允许（食物不会出现在蛇身上，因此该步必然不增长）。

### 3.3 两种路线优劣

| 维度 | 图搜索（安全 A*） | 哈密顿回路（+捷径） |
| --- | --- | --- |
| 安全性保证 | 启发式：虚拟蛇/追尾能避免绝大多数死路，但残局无理论保证 | 可证明：不变量保证永不撞墙/撞身 |
| 通关率（实测） | 10×10：50%；有障碍：0%（吃满 86–97%） | 无障碍（含奇×奇）/宏格障碍：100% |
| 路径效率 | 早期极快（≈曼哈顿距离）；残局大量追尾绕圈 | 纯回路平均 N/2 步/食物；捷径后 10×10 下降 12%（2419→2133 步） |
| 单步开销 | 2–4 次 BFS/A* + 最长路径扩展，O(N)–O(N·L) | O(1)（查表），捷径 O(4) |
| 预处理 | 无 | 回路生成 O(N)（生成树法 O(宏格数 log)） |
| 地图适应性 | 任意地图（含单格障碍、动态障碍） | 要求回路存在：无障碍或宏格对齐障碍；任意障碍时需退化 |
| 内存 | 峰值节点 ~ N，若干 Uint8Array/Int32Array | 两张 Int32Array（cell↔idx） |
| 多食物/有效期 | 天然支持（按距离排序尝试） | 按回路序取最近前方食物，过期不影响安全 |

## 5. 可运行方案：语言、依赖、数据结构与决策流程

### 5.1 目标语言与运行环境

- 语言：TypeScript 5；框架：React 19 + Vite 7 + Tailwind 4；渲染：Canvas 2D；基准：Web Worker（module）。
- 运行：现代浏览器（Chrome/Edge/Firefox/Safari）；构建产物为单页静态文件，无后端。开发：`npm install && npm run dev`；构建：`npm run build`。
- 引擎无 DOM 依赖，可在 Node 中直接跑批量验收（本报告基线数据即由 Node 运行 `src/engine` 得到）。

### 5.2 核心数据结构

| 结构 | 类型 | 用途 / 复杂度 |
| --- | --- | --- |
| Grid.nbr | Int32Array(N×4) | 预处理 4 邻接（越界/障碍为 −1），所有搜索共享，O(1) 取邻居 |
| Game.buf | Int32Array 环形缓冲 | 蛇身 尾→头 序列，O(1) 推头/弹尾 |
| Game.occ / visited | Uint8Array(N) | 占用位图（O(1) 碰撞）/ 覆盖位图（覆盖率） |
| Game.foodAt | Int32Array(N) | 格子 → 食物下标，O(1) 判断进食；FoodItem 记录出生/过期步 |
| HamiltonCycle.index / cells | Int32Array(N) / Int32Array(L) | cell↔回路序号双向映射；aliasCell 处理奇×奇角格 |
| 搜索缓冲 | dist/parent/queue Int32Array + 时间戳数组 | 复用缓冲、时间戳代替 fill 清零，避免每步分配（增量/缓存手段） |

### 5.3 决策流程（混合策略）

```text
decide(game):
  if cycle 存在:                                  # 预处理阶段：zigzag / 缺角别名 / 宏格生成树
    headRel = rel(head); foodRel = min{ rel(f) : rel(f) > headRel }
    natural = 邻格中 rel 最小且 > headRel 者（别名格上有食物则优先）
    best    = 邻格中满足 headRel < rel ≤ foodRel 且 L − rel ≥ 2+食物数 的 rel 最大者
    return best ?? natural                         # O(1)
  else:                                          # 任意障碍地图 → 安全搜索
    for 每个食物 按 A* 距离升序:
      p = A*(head → food);  if 虚拟蛇(p) 安全: return p[1]
    for 每个食物: lp = 最长路径(head → food); if 虚拟蛇(lp) 安全: return lp[1]
    tail = (饥饿逃逸 ? BFS : 最长路径)(head → tail);  if tail: return tail[1]
    return 洪水填充空间最大的邻格 ?? -1            # -1 = 被困
```

### 5.4 路径规划流程小结

- 预处理：生成障碍 → 构建邻接表 → 尝试构造回路（失败则标记为搜索模式）。
- 每步：读取状态 → 决策（上表）→ 计时/计节点 → 执行移动 → 处理进食/过期/补生 → 终止判定。
- 可视化：紫色为回路、蓝色为当前规划路径、食物颜色随剩余有效期由绿变红、暗色底纹为已覆盖格。

## 7. 困难场景适配方案

### 7.1 各困难条件下算法是否成立 / 是否需改造 / 如何调整

| 困难条件 | 图搜索（安全 A*） | 哈密顿回路 | 本方案采取的改造 |
| --- | --- | --- | --- |
| 固定/随机障碍 | 成立，无需改造；但残局“口袋”导致吃满率上限 86–90% | 任意单格障碍：一般不成立（奇偶性、NP-完全）；宏格对齐障碍：成立 | ① 障碍生成拒绝死胡同与孤岛；② 宏格障碍 → 生成树回路（100%）；③ 单格障碍 → 退化安全 A* + 饥饿逃逸 |
| 食物随机不可预测 | 成立：每步重规划 | 成立：回路对食物位置无假设，捷径按回路序选最近前方食物 | 每步局部重规划（A*）；回路模式 O(1) 查表 |
| 蛇身变长搜索空间扩大 | 搜索图反而变小（自由格减少），但最长路径扩展与虚拟蛇次数增加 | 不受影响（O(1)） | 复用缓冲 + 时间戳；候选食物按距离排序、首个安全即返回 |
| 有限时间连续决策 | 单步 O(N)–O(N·L)，20×20 实测最大 ≈ 4 ms（预算 16 ms） | 恒定微秒级 | 预算内：优先 A*；超预算风险：可跳过最长路径绕行，直接追尾（anytime 降级） |
| 地图扩大 20×20 / 30×30+ | 成立；每步开销线性增长，30×30 估计单步最长 20–40 ms | 成立且开销不变；纯回路步/食物 ∝ N，总步数 ∝ N²（30×30 约 20 万步） | 大图必须用回路 + 捷径；搜索类需分层/局部搜索（见 7.4） |
| 多食物 / 有效期 | 成立：按 A* 距离排序依次校验 | 成立：选回路序最近的前方食物；过期后自动改追下一个；安全裕量 +食物数 | 困难 A 已验证 100%；过期只影响效率不影响安全 |
| 动态障碍（极限） | 天然适配（每步重规划），但需“障碍出现在蛇身/路径上”的规则 | 不成立：回路会被破坏，需增量修复 | 见 8.4 极限难度设计 |

### 7.2 失效场景与死局 / 不可达检测

- **被困检测**：蛇头 4 邻格均不可进入 ⇒ 立即失败（贪心 A* 的主要死法）。**提前预警**：洪水填充从蛇头出发看不到蛇尾且可达格数 < 蛇长 ⇒ 已进入必死区域。
- **食物不可达**：A* 返回 null；此时不应等待而应追尾，让身体移动后再试。**永久不可达**（口袋）：食物邻格全部为蛇身且蛇身构成稳定环 ⇒ 饥饿计数增长；本方案以 6N+100 步为死循环判据，并用饥饿逃逸尝试打破。
- **结构性不可行**（预处理即可判定）：奇×奇无障碍地图无回路（用缺角别名回路解决）；含度数 1 自由格的地图不可能 100% 覆盖（生成器直接拒绝）；自由格黑白数不等的障碍地图不存在回路（哈密顿模式直接放弃）。
- **为何单格障碍下搜索类无法 100%**：近满盘时蛇身是长度 ≈ N−k 的固定环，剩余 k 个自由格是环外“口袋”；网格是二分图，把一个单格并入环需要改变环长的奇偶性，而蛇无法“原地重排”，因此除非口袋恰能以两格对为单位并入（最长路径扩展正是做这件事），否则永远吃不到。这就是残余损失的口袋来源。需诚实说明：试图用静态割族（单刀割、2×2 块割、区域塔）从布局推出非平凡上界的尝试**未成功**——本场景的障碍生成规则已排除死胡同与孤岛，剩余布局黑白平衡且连通，所有静态上界均≥96%（实测均值 88% 与上界的差距来自蛇身动态围出的过程性口袋，依赖轨迹而非布局固有结构）。因此「86–88%」目前是实测经验值 + 过程性机理解释，不是已证明的逐图上界；将其升级为可计算上界需要把蛇身轨迹纳入约束（T-join on 剩余图），列为开放问题。

### 7.3 搜索速度与路径质量的平衡

- 决策链按“代价升序、质量降序”排列：A*（最快、最短）→ 最长路径绕行（较慢、更安全）→ 追尾（慢、零收益但绝对安全）→ 洪水填充（兜底）。任何一级超预算即可截断，后续级别给出可行解（anytime 结构）。
- 回路捷径中的裕量参数（2 + 食物数）与“不越过食物”规则是效率/安全的旋钮：裕量越大越保守；去掉“不越过食物”会导致跳过食物后绕整圈。
- A* 的 tie-break（f 相同优先 h 小）比朴素 BFS 少扩展约 30–50% 节点，路径长度不变。

### 7.4 预处理、缓存、增量搜索、局部重规划

- **预处理**：邻接表 `nbr`；哈密顿回路（zigzag O(N)，生成树 O(M log M)，M 为宏格数）；障碍合法性（度数、连通、黑白平衡）。
- **缓存**：搜索缓冲区全局复用 + 时间戳标记（免清零）；回路策略本身就是“预计算好的全局路径缓存”。
- **增量搜索**：现有实现每步全量 A*（N ≤ 400 时 < 1 ms）；30×30+ 建议改为 D* Lite / LPA*，在蛇身移动仅改变少量格子占用时增量更新 g 值，或者只在“规划路径被新占用格打断”时重规划（懒重规划）。
- **局部重规划**：安全 A* 天然每步重规划；回路策略只在捷径判定处局部决策。极限难度下可采用“回路 + 局部窗口修复”：障碍变动时只在受影响宏格的邻域内重新缝合生成树（局部 Prim 重连），其余回路序号保持不变。

## 8. 分级实现路线与各级指标

### 8.1 基础难度（10×10，无障碍，单食物）

- 路线：zigzag 回路 + 单调序捷径（混合策略）。
- 指标：通关 100%（10/10），吃满 100%，覆盖 100%，平均 2133 步（纯回路 2419，安全 A* 2040 但仅 50% 通关），平均决策 < 0.001 ms，峰值节点 0，内存 ≈ 4 KB。

### 8.2 中等难度（15×15 / 16×16，随机障碍，单食物随机）

- 路线 A（宏格障碍，推荐）：生成树回路 + 捷径。通关 100%，吃满/覆盖 100%，平均 ≈ 1.29 万步，决策 ≈ 0.001 ms。
- 路线 B（任意单格障碍）：安全 A* + 饥饿逃逸（混合策略退化分支）。通关 0%，吃满 88.0%（安全 A* 86.1%），覆盖 100%，平均 ≈ 9500 步，平均决策 0.007–0.009 ms，最大 ≈ 0.6–4.5 ms，峰值节点 ≈ 620，内存 ≈ 20 KB。失败原因 100% 为饥饿（口袋不可达）。
- 路线 B 的改进上限分析：口袋问题是拓扑性的；要突破 90% 需引入“覆盖全部自由格的环”思想——(i) 回溯 + Warnsdorff 启发式搜索一般图上的哈密顿回路（207 格规模通常可在毫秒–秒级找到，但无保证且要求黑白平衡）；(ii) 允许“别名格”的近哈密顿回路（把与回路上距离 2 的两个格相邻的孤立格作为旁路）；(iii) 在障碍生成阶段就约束为宏格对齐（即路线 A）。若无法改变地图规则，实测最高吃满率约 88%，理论上界取决于口袋数（每个不可并入的单格口袋损失 1 格）。

### 8.3 困难难度（20×20，障碍，3 食物，有效期 200 步）

- 路线 A（宏格障碍）：回路 + 捷径。实测通关 100%，吃满/覆盖 100%，平均 1.22 万步（纯回路 1.38 万），决策 ≈ 0.0002 ms，最大 < 1 ms，0 节点。过期食物只造成效率损失。
- 路线 B（单格障碍）：安全 A* / 混合。通关 0%，吃满 ≈ 89.7–89.8%，覆盖 ≈ 99.9%，平均 1.24 万–1.29 万步，平均决策 ≈ 0.015 ms，最大 ≈ 1–2 ms（远低于 16 ms 预算），峰值节点 ≈ 1440，内存 ≈ 44 KB。失败原因：饥饿 9/10、被困 1/10。
- 实时性：两条路线单步均在 16 ms 预算内，超预算比例 0%。

### 8.4 极限难度 A（30×30，动态宏格障碍，5 食物，有效期 80，2 ms/步）—— 已实装并通过验收

> **验收结果（extreme-dyn 场景，seed 7000–7099，100 局）：通关 100%（目标 ≥90%），吃满 100%，单步 p99 0.19 ms（目标 ≤2 ms），双判据降级单元自检 7/7；1/100 局由墙钟保险丝触发降级、降级后仍通关（降级段 p99 0.12→0.26 ms）。** 实现：`src/engine/dyn.ts`（DynamicCycle / DynScheduler / DegradeController）+ `hamilton-dyn` 策略；验收脚本 `scripts/bench-dyn.ts`（100 seeds + 降级前后分段 p99 观测 + 双判据单元自检）。

- **规则设计**：障碍以 2×2 宏格为单位周期性增减（每 40 步最多 2 块），出现前 15 步进入**预约位**（reserved）——策略视为不可通行、食物生成避开、蛇身不得进入；因此“障碍落地砸中蛇身/食物”在规则层面不可能发生，通关定义保持良构。30×30 静态底图密度 8%，宏格图连通。
- **宏格环缝合（回路增量维护）**：回路表示为自由格上的 2-正则环（next/prev 双映射）。拆除宏格 = 把每条张开侧邻居的出/入端（必然网格相邻）直连闭合；插入反之。所有拼接边都在同一宏格侧内，**绝不产生跨块“传送边”**——早期实现直连前后外邻居产生传送边，蛇身弧跨断点、原地徘徊自围。每次变异后沿 next 走一圈校验单环不变量，失败即快照回滚（含 idx 快照）并拉黑该方向：重试零 walk 成本。
- **双判据降级（目标中的“p99 超标立刻降级”）**：**判据 A（确定性主判据）**：窗口（50 步）内单步 walk spike（>6 次重编号）占比 >20% —— 捕捉缝合重试风暴；**判据 B（实时性保险丝）**：窗口 p99 墙钟 > max(5×预算, 5 ms) —— 只在真实慢环境兜底。不直接用墙钟做主判据的原因：实测机器负载抖动会让同一 seed 的降级点漂移、结果不可复现（单跑赢、连跑输）。降级后切**「安全优先」**：纯回路 O(1) 前进、禁捷径；缝合维护继续（正确性必需），unblock 重试走指数退避且不可放弃（放弃会让回路 N 缩水、蛇爬出回路自围）。
- **实测教训（本轮调试记录）**：① 捷径裕量误用绝对回路序号（`N − r`）而非相对蛇尾距离——动态重编号后序号起点任意，捷径把头落到蛇尾紧后方自断后路（10/10 局 no-move 根因），修复为 `gap − rel ≥ margin`；② 终局 gap==1 时拓扑后继恰为尾格，被候选集的 occ 过滤误杀——头进尾格合法（尾同让），放行后满盘前死锁消除；③ unblock 只还格子不缝回回路 ⇒ 回路 N 单调递减、蛇爬出回路自围；④ 回滚快照必须含 idx（rewalk 失败会清空重编号表）；⑤ 改 grid.blocked 后必须 rebuildNeighbors（生成树法读预处理邻接表，旧表残留内部边使重建恒 null）；⑥ rebuildFn 必须叠加全部 reserved 预约位——否则 unblock 重建把预约格缝回回路，头的后继变成预约格（seed 7030 死因）。
- **2 ms 预算分析**：沿回路步进 O(1)（查表 + 4 邻格）；宏格增删走 O(N) 生成树重建（预热后 p99 0.6 ms）；100 局单步 p99 1.23 ms（事件生效基线；早前 0.69 ms 为事件未生效口径，见上方声明）、超预算步数 2139/504 万（0.042%）。注：动态场景覆盖率可 >100%（visitedCount 含“到访后变为障碍”的格），以吃满率为准。
- **工程修复（rebuildNeighbors 时序）**：rebuildFn 叠加/恢复 pendingMacroCells 改 blocked 后必须调 `grid.rebuildNeighbors()`——生成树法读预处理邻接表，旧表残留被摘宏格的内部边会让遍历/缝合错乱恒返 null（实测 513 次重建全 null 的根因，修复后事件正常触发）。调度器另加三层防抖：距蛇头 ≥8 预筛、割点 O(宏格数) 预检、每周期昂贵尝试 ≤3 次——事件步 p50 0.4ms / max 1.5ms。

### 8.4.2 步数优化空间实测（诚实结论）

针对验收目标「平均总步数 ↓≥5%」，实装并 A/B 了三项捷径优化：条件性越食捷径（跳过最近食物落到其与下一食物之间）、终局 margin 收窄（baseMargin 2→1）、路径食物计数（裕量按落点→目标食物间实际食物数计，替代全场食物数）。隔离矩阵（hard 场景 20 seeds）结果：**越食档 0 影响（触发率结构性极低——margin=食物项+2 已覆盖其窗口）、终局收窄 +0.9%（反向劣化）、全开 +0.9%**。三项实验开关默认关闭（`OVERFOOD_SHORTCUT / ENDGAME_MARGIN`），保留代码供复现。

原因分析：extreme-dyn/hard 的步数由「回路遍历 + 动态事件绕行」主导（每 40 步宏格变动强制改变最短路径）， 捷径机会密度（spanning-tree 回路实测 0.29/格，zigzag 仅 0.18）已接近饱和——**margin 维度无 ↓5% 空间**。 该结论本身即实验产出：后续步数优化应转向「事件调度与回路形态的联合优化」而非捷径参数。

### 8.5 核心不变量与证明骨架（§8.4 方案的正确性论证）

动态回路方案依赖四个不变量。以下给出书面证明骨架；运行时由 `verifyStructure`（结构校验器）、性质基随机测试（`scripts/property-test.ts`，≥10⁴ 操作）与故障注入测试（`scripts/fault-test.ts`，5 项注入 246 万次事件）三重实证支撑。

**论证结构的三条边**（评审视角的正确性分层）：沿回路步与捷径步的不变量由构造**推导保持**；重建步会重新编号，I2 不是被保持而是被**放弃后验证重建**（靠 verifyStructure + monoArcChecker）；墙钟耗时等机器相关量属**实测层**，单独一列不混入保证。影子 refinement 测试独立重建参考回路，验证同一支持集上的合法可构造性；由于哈密顿回路可能不唯一，canonical 精确序列只作拓扑观测，不作为失败门。

### 8.5.1a verifyStructure 完备性小证明

**命题**：verifyStructure 通过（返回 null）⟺ 链接集 L = {c : next[c] ≥ 0} 构成恰为 expectedN 个自由格的单一简单环，且全部链接网格相邻、next/prev 对称。

**证明**：（⇐）若 L 是合法单环，从任一格沿 next 走一圈恰访问 expectedN 格且回到起点，四项检查逐一满足：环遍历计数 = N（检查 1）、每格 next ≥ 0（检查 2 隐含）、每步 dx+dy=1（网格相邻检查）、prev 沿环一致（对称检查）、所有 next ≥ 0 的格都在环上（无第二环检查）、idx 与环一致（序号检查）。各项均通过。（⇒）反证：若检查全过但 L 不是单一简单环，则 (a) 存在格 next[c] < 0 且 idx[c] ≥ 0——被「无第二环」检查捕获（该格有 idx 但环走不到）；(b) 存在环外格 next[c] ≥ 0——环游计数 < linked.length，被覆盖检查捕获；(c) 某步 dx+dy ≠ 1——被网格相邻检查捕获；(d) prev 不对称——被对称检查捕获。四类反例穷尽了「非单一简单环」的所有可能（环定义的否定 = 多环 / 链 / 断裂 / 非对称，各自对应一项检查），故通过 ⟺ 合法。∎

| --- | --- | --- |

### 8.5.1 引理（直连折叠不可行）：为什么宏格摘除必须走 O(N) 重建

- **枚举证明**：O(1) 缝合的直觉方案是把 B 在环上的每段路径 x→[B 内路径]→y 直连为 x→y。设 x 与 B 进入格 p 网格相邻、y 与 B 出格 q 网格相邻，直连合法要求 x 与 y 也网格相邻。对 (p,q) 全部 12 种有序组合枚举：仅当 x、y 恰在 B 同一外侧线时成立，但回路取向由环流方向决定，实际出现的段两端外侧格呈「列差 3」（直边穿越，如 137→[138,139]→140 的两端 (4,17) 与 (4,20)）或「对角」（对角穿越）——均不相邻。故 2×2 宏格 + 4-邻接下直连折叠不可行。
- **实测印证**：按同侧配对与相邻配对的两种 O(1) 实现均产生传送边（verifyStructure 报对角边 379→350、8 格侧环），全部被拦截回滚。结论：正确手术只有全量生成树重建（O(N)≈900 格，预热后 p50 0.15ms / p99 0.6ms），正确性由 I1 构造论证 + verifyStructure 把关。
- **成本控制**：重建只在调度事件触发。为防「失败重试风暴」（每个被拒候选烧一次重建，实测单步 31 次 = 11ms），调度器对 block 候选做 O(1) 距离预筛（距蛇头 ≥ 8）并限制每周期最多 3 次昂贵尝试；unblock 重试走指数退避。事件步实测 p50 0.4ms / max 1.5ms，全部在 2ms 预算内。开局做 50 次 JIT 预热重建，消除冷启动尖峰。

> **实证三件套**：① 性质基随机测试 10⁴ 次宏格增删序列，P1–P4 不变量断言全过；② 故障注入 **246 万次事件**（5 项：重建失败 30% 触发 11.1 万次、单调弧拒绝触发 234 万次、周期强降级 5198 次等），全部「终态合法 + 引擎状态无污染」；③ 100 seeds 验收 100% 通关 @ p99 1.23ms（事件生效基线）。书面证明给「为什么对」，三件套给「确实对」——两者互补，缺一不可。

### 8.5.2 「完美通关」的严格定义（S/C/N/V 四性质）与对手分级

现有胜利判据 `length ≥ freeCount` 存在定义漏洞：动态场景下 `freeCount` 随对手行为**递减**——障碍落得越多通关阈值越低，且 `applyBlock` 会删除落在障碍上的食物（对手可直接删掉目标）。为堵住该漏洞并把「通关」从单一数字升级为可分别检验的性质组合，定义如下四条：

| 性质 | 陈述 | 判定方式 | 现状 |
| --- | --- | --- | --- |
| S 安全 | 对局全程不进入非法状态（不撞墙/自身/障碍/预约位） | 引擎硬拦截 + 基准失败门 | ✅ 每次验收硬性检查；样本通过不等于对任意对手的无条件证明 |
| 初始容量诊断 | 终止时记录 `final_length / initial_freeCount`，分母锚定开局自由格数。 | bench-dyn 诊断列 | ⚠️ 没有 structural_L 证书时不能单独宣称 C 已满足 |
| 到期快照可达性 | 食物自然到期时，记录它在“障碍 + 预约位 + 当前蛇身”静态快照中是否可达 | expiredReachableSnapshot / expiredUnreachableSnapshot | ⚠️ 诊断指标；不等于能在 TTL 内吃到，也不是 N 活性证明 |
| V 覆盖 | `coverage = \|visited ∩ 当前自由集\| / \|当前自由集\|`——被障碍覆盖的到访格不再计入，覆盖率天然 ≤100% | 引擎覆盖统计改造 | ✅ 已实装（coverageCurrent） |

**对手分级**（决定 S/C 可达性的对手模型）：**A0** 静态障碍（已 100%）；**A1** 障碍有 T 步预告、不落在蛇身（当前 extreme-dyn 档，事件真实生效后仍 100% 通关）；**A2** 有预告、可落在蛇头正前方但不落在蛇身（extreme-dyn-a2 已实装，见下）；**A3** 无预告、可落在蛇身——此档**不存在必胜策略**（满盘阶段蛇头度数为 1 是常态，对手单周期即可封死），唯一可辩护的验收是相对的：每次失败附带「对手强制」证书（离线回溯免责搜索，k≈8 步、分支 ≤3 的有界验证）。

**A2-like 的公平性条件**：① 预约集不得覆盖蛇头现阶段全部合法后继；② 预告期 T ≥ 2；③ 落地后自由区保持连通。**诚实边界**：维护器仍可拒绝通过这些检查的候选，逃逸承诺锁死模式也未实装，所以当前场景不是严格 A2。基准脚本会公开策略拒绝数量。

> **历史 A2-like 样本**曾在 100 局与 800 局矩阵中全胜；这些数字只适用于当时 commit、seed 和筛选规则。新版输出同时列出策略拒绝与提交事件，不能用成功提交数代替严格对手验收。

> 迁移期基准并列：bench-dyn 输出旧 fillRate、初始容量比例、V 覆盖率与到期快照可达性。后两类诊断不会再被命名为已经证明的 C/N 性质；“100%”只表示给定样本全胜，不代表总体成功率定理。

## 9. 推荐实现路线及理由

> **推荐：混合策略 = 哈密顿回路（zigzag / 缺角别名 / 宏格生成树）+ 单调序捷径，回路不可构造时退化为安全 A*（虚拟蛇 + 最长路径 + 追尾 + 饥饿逃逸）。**

- **正确性优先**：回路 + 单调序捷径有形式化不变量，是唯一能在基础/中等 A/困难 A 上做到 100% 通关的路线（实测基础/中等 A/困难 A 共 30/30 局全部通关，另在 15×15、11×9、30×30 宏格障碍等附加地图上亦全部通关）。
- **效率可接受**：捷径把纯回路的总步数降低 12–13%，且决策为 O(1)，天然满足实时性与大地图要求。
- **可退化**：面对任意障碍/动态障碍等回路不成立的场景，安全 A* 分支保证“尽可能接近通关”（吃满 88–90%、覆盖 100%）并给出明确的失败原因。
- **工程简单**：核心代码约 600 行 TypeScript、无第三方算法库；引擎与 UI 解耦，可在 Node 中批量验收。
- **进一步提升方向**（按性价比）：① 障碍规则改为宏格对齐（零算法成本换 100%）；② 一般图哈密顿回路搜索（回溯 + Warnsdorff，带节点预算）；③ 极限难度的回路增量修复。

## 10. 验收流程与复现方法

- 打开“基准测试”页，勾选难度与策略，设置基础种子（默认 1000）与每组局数（默认 10），点击开始；进度与每局结果实时显示，完成后可导出 JSON（含逐局 seed、结果、步数、耗时、节点数、失败原因）。
- 验收判据：通关率 = 通关局数 / 总局数；每局报告吃满率、覆盖率、总步数、步/食物、平均/最大决策时间、超预算比例、峰值节点/内存、失败原因。
- 复现：相同 (场景, 策略, seed) 下，通关结果、步数、节点数逐位一致；耗时受机器影响仅作参考。
- “实时演示”页可用同一 seed 单步回放任意一局，勾选“显示回路/路径”观察决策依据。
- Node 批量验收：仓库内置 `scripts/bench.ts`，运行 `npx esbuild scripts/bench.ts --bundle --platform=node --outfile=/tmp/bench.js && node /tmp/bench.js all 10 1000`（参数：场景 id 或 all、局数、基础种子），即本报告第 6 节基线数据的生成方式。
