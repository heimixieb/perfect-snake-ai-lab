# 贪吃蛇「完美通关 AI」项目说明

> ⚠️ 历史评审稿：本文保留早期实验叙述，不作为当前版本的验收契约。当前指标定义、A2-like 筛选边界与复现命令以 README.md 和 docs/verification.md 为准。

（供教师评审的技术文档 / 项目：TypeScript + React + Canvas，约 4600 行，构建产物为单文件 HTML）

---

## 一、题目与目标

在贪吃蛇上实现并严格验证「完美通关 AI」：蛇不撞墙、不撞自身，吃掉地图上全部食物（蛇长 = 全部可通行格数），格子覆盖率 100%。在三类难度递增的环境下达标：

1. **静态障碍**：宏格对齐（2×2）或单格随机障碍；
2. **极限动态障碍**：30×30 地图，障碍每 40 步周期性出现/消失（出现带 15 步预告），同时 5 个食物且有效期 80 步，**每步决策预算 2ms**；
3. 全程守住两条红线：**可证明的 100% 通关** 与 **2ms 实时预算**。

---

## 二、核心思路：两条互补的通关路线

### 路线 A：哈密顿回路 + 单调序捷径（主路线，可证明 100%）

把地图自由格构造成一条**哈密顿回路**（经过每个可通行格恰好一次的环），蛇永远沿回路单调前进。三种构造方法覆盖三类地图：

| 构造方法 | 适用地图 | 说明 |
|---|---|---|
| zigzag 蛇形 | 偶数×偶数无障碍 | 经典蛇形回路 |
| 缺角别名回路 | 奇数×奇数（如 15×15） | 由二分图奇偶性可证奇×奇无哈密顿回路；构造覆盖 N−1 格的回路，把跳过的角格赋予「别名序号」并入回路，仍可 100% 覆盖 |
| 宏格生成树法 | 2×2 宏格对齐障碍 | 把地图切成 2×2 宏格，自由宏格图上跑随机 Prim 生成树，每个宏格是一个 4 格小环，沿树边把小环两两「缝合」成大环 |

**捷径**：蛇沿回路走太慢（步数 ∝ N²/4），因此允许「抄近道」——跳跃有严格安全条件（下文 I3），跳跃后仍沿回路前进，安全性可证明。

### 路线 B：图搜索 + 虚拟蛇验证（备用，应对回路不存在的地图）

对回路无法构造的地图（任意单格障碍等），采用 stevennl/Snake 的经典策略并加以改进：

1. BFS/A* 最短路吃食物；
2. **虚拟蛇校验**：模拟吃完后蛇能否追到自己的尾巴（能追到尾 ⇒ 永远有退路）；
3. 失败则走「最长路径」追尾拖延，等待局面打开；
4. 饥饿逃逸：长时间追尾时交替使用最长/最短路径打破稳定死循环；
5. 洪水填充空间最大化兜底。

**为什么不用强化学习**：同题权威开源实现（chuyangliu/snake，1791★）实测图搜索 94% 通关、Double DQN 仅 50%。学习类方法无法提供通关保证，故只作对照、不进主路线。

## 三、正确性论证（项目重点之一）

### 3.1 四个核心不变量（均有书面证明骨架 + 实证）

- **I1 单环性**：每次障碍增删维护后，回路仍是自由格上的单一简单环，全部链接为网格相邻边。
- **I2 蛇身单调弧**：蛇身各格的回路序号从尾到头严格单调递增（允许空隙的弱化弧形式——这是捷径安全性真正需要的）。
- **I3 捷径安全裕量**：头跳到候选格 c 安全 ⇔ rel(c) ∈ (0, gap) 且不越过最近前方食物且 gap − rel(c) ≥ 2 + 食物数。三项分别保证单调前进、不越过蛇尾、吃食尾巴停一步后不撞尾。
- **I4 预约位安全**：动态障碍落地前 15 步进入「预约位」，策略、食物生成、引擎三层硬拦截，落地时蛇身必然已避开。

### 3.2 一个反直觉引理：O(1) 缝合为什么不可行

动态障碍下维护回路的直觉方案是把被摘宏格的环上路径「直连折叠」。我们用穷举 + 实测证明**该方案在 2×2 宏格 + 4-邻接约束下不可行**：对进/出格 12 种组合枚举，直连合法要求两端外侧格网格相邻，但实际回路取向产生的两端呈「列差 3」或「对角」——均不相邻，直连必产生「传送边」（实测三种 O(1) 实现全部被结构校验器拦截）。因此正确的维护手术是 **O(N) 全量生成树重建**（预热后 p99 0.6ms，仍在 2ms 预算内），正确性由构造论证 + 运行时结构校验器把关。

### 3.2.1 论证级升级：2-factor + 圈合并增量维护（twofactor.ts）

该引理否掉的是 O(1) 拼接，不否 O(局部) 修复。本项目进一步把维护对象从「单一回路」升级为「支持集上的 **2-factor**」（每个自由格恰 2 条网格相邻链接），二者关系：单环是 2-factor 的特例，提交前用圈合并把所有圈缝成单环即可复用既有单环步进逻辑（提交视图与经典引擎逐字段兼容）。

四个组件（均为多项式可解或 O(局部)）：

1. **b-matching 流求解**（初始化 + 结构兜底）：网格是二分图，2-factor ⟺ 二分图满流——S→黑格容量 2、黑白边容量 1、白格→T 容量 2，Dinic 求解，满流 ⟺ 存在 2-factor。宏格对齐布局黑白恒平衡（每 2×2 宏格恰 2 黑 2 白）。
2. **平行边缝合（2-switch）**：相邻两圈各断一条边 (u,p)/(v,r)、交叉重连 (u,v)/(p,r)，要求 (p,r) 网格相邻——两圈剪弦交叉重连必并成一环，每次净减一圈。
3. **对角 reroute**：缝合条件不满足（两圈对角相触）时，断开 (u,p) 制造一对亏格，从 u 做「首跳强制 = v」的交替增广路 BFS（b-matching 残量图，格×相乘积图），翻转后两圈链式并成一环——实测场景合并所需。
4. **亏格森林增广（增量修复）**：宏格摘除/缝回只切断 O(1) 条边界链接，产生 O(1) 个亏格格（度<2）；在亏格间找交替增广路重连（中间格去一条补一条、度数不变）。**完备性论证**：一轮无任何增广路 ⟹ 残量图无 Berge 路 ⟹ 当前 b-matching 已是支持集上的最大基数（增广路定理）——不足满配即支持集上确实无 2-factor，拒绝事件有构造性依据而非猜测。

**当前复核（50 seeds 专项测试）**：8659 个结构校验点全过；1995 个对照事件中精确一致 1757 次、仅 2-factor 接受 6 次、仅全量重建接受 232 次，不能称为逐事件完全一致或严格不劣。事件级中位/p99 为 0.042/0.224ms，全量重建对照为 0.167/0.869ms。历史 100 局整局数据仅保留作当时版本记录。

**真实 2-factor 圈分解统计**（修正 b-预研探针的引用口径）：宏格对齐布局上流解原始圈数均值 20.8（medium）/ 67.3（extreme-dyn），跨圈正交邻接对占比 23–25%（平行边缝合机会），对角相触对每布局 9–10 个（reroute 必要性实证）。

### 3.3 实证三件套

书面证明回答「为什么对」，以下自动化验证回答「确实对」：

1. **性质基随机测试**（property-test.ts）：随机宏格增删序列 ≥10⁴ 次操作，四个不变量逐操作断言，零违例；
2. **故障注入测试**（fault-test.ts）：五种注入（重建失败 30%/全程、单调弧校验拒绝 50%、周期性强降级、极端时钟采样），累计 **246 万次注入事件**，全部「终态合法 + 引擎状态无污染」；**覆盖度指标**两级输出——①逐注入项输出不变量分支触发计数（结构校验通过/回滚/降级原因分布/失败原因分布/事件放弃后继续）+ 调度器事件结局空间（落地/预约拒绝/落地回滚/缝回放弃，实测 4/4 结局全被触发）；②5 类违例检测分支计数（传送边/第二环/prev不一致/覆盖缺失/序号错乱），配**检测分支活性探针**（对合法回路合成注入 5 类破损，证明每个检测分支可命中——真实运行中计数为 0 即「真零」：引擎从未产出被检测分支捕获的违例，而非检测失效）。回答「哪些不变量分支被实际触发过」而非仅「没崩」——数字大小不说明验证强度，分支覆盖分布才说明；
3. **100 seeds 基准验收**（bench-dyn.ts）：见下表。

调试中实际抓到并修复 6 个真 bug（捷径序号基准错误、终局尾格后继误杀、unblock 不缝回回路、回滚快照缺 idx、rebuildNeighbors 时序缺失、预约格被缝回回路），全部记录在报告「实测教训」一节——这些都是单靠跑分发现不了的。

## 四、量化结果

### 4.1 静态场景（每组 10 局，seed 1000–1009，可逐位复现）

| 场景 | 最优策略 | 通关率 | 吃满率 | 单步平均耗时 |
|---|---|---|---|---|
| 基础 10×10 无障碍 | 哈密顿+捷径 / 混合 | **100%** | 100% | 0.001 ms |
| 中等 16×16 宏格障碍 | 同上 | **100%** | 100% | 0.001 ms |
| 困难 20×20 + 3 食物 + TTL | 同上 | **100%** | 100% | 0.001 ms |
| 中等 15×15 单格障碍（回路不存在） | 安全 A*（备路线） | 0%（吃满 77–93%，30 局均值 79%，覆盖 ≈100%） | — | 0.01 ms |

单格障碍场景的吃满率上限是**结构性**的：死胡同格与奇偶性使部分食物物理不可吃，任何算法都无法突破——报告中给出了机理论证。

### 4.2 极限动态障碍场景（extreme-dyn，本次迭代核心）

- **通关率 100%**（100 局，目标 ≥90%）；
- **单步 p99 = 1.23ms**（目标 ≤2ms；早期 0.69ms 测于事件未生效状态，已作废），超预算步数占比 0.042%；
- 压力矩阵 8 组合（预告期 5/15 × 变动数 2/4 × 密度 0.08/0.12）：7 组 100% 通关，唯一 83% 组合的失败模式是「优雅降级」（放弃个别事件），无死锁、无非法状态——**崩溃边界已标定**；
- **A2 档压力矩阵**（同轴 8 组合 × 各 100 局 = 800 局大样本，事件必须落地）：**8/8 组合 100% 通关**，合法终态 + 结构完好 + 零死锁，落地事件 429,450 次回滚放弃 0，p99 峰 1.54ms——崩溃边界未触及（npx tsx scripts/a2-matrix.ts 100 7000）；
- **规模扩展性**（scripts/scale-test.ts，30→50→100，面积 11.1×）：O(1) 决策步进与规模无关（0.0047→0.0047→0.0049ms，动态档 0.0054ms 三档全等）；O(N) 构造次线性（0.31→0.49→2.19ms，7.05×）；O(N) 事件重建 0.16→0.46→3.63ms（线性可见，p99 ≈3ms）——扩展瓶颈在重建（O(N) 可证正确手术），不在决策侧；全部档位通关 100%（npx tsx scripts/scale-test.ts）；
- p99 超标时的降级路径按设计工作：自动切「安全优先」模式（纯回路 O(1) 前进、禁捷径），宁可绕远不冒风险；
- **A2 对手档 100 局大样本**（extreme-dyn-a2，事件必须落地、可落蛇头正前方）：**100% 通关**，C 完成率 99.8%，单步 p99 1.09ms；
- **2-factor 增量引擎对照**（--twofactor）：同 100 局通关 100%、单步 p99 0.11ms（经典 1.13ms）、超预算 0.002%——详见 §3.2.1。

## 五、工程要点

- **引擎与 UI 解耦**：核心逻辑无 DOM 依赖，Node 命令行与应用内 Web Worker 跑同一引擎，基准结果逐位可复现（同 seed 同结果，含失败路径）。
- **性能**：整数格 + TypedArray 位图、环形缓冲蛇身、预处理邻接表、复用缓冲 + 时间戳标记；决策热路径零分配。单次宏格重建经 JIT 预热后 p99 0.6ms。
- **可观测性**：结构校验器（单环/2-正则/网格相邻/序号一致四项检查）内置于每次重建；UI 提供「不变量监控」开关实时显示断言状态、预约位与降级状态；画布可视化回路、预约位与规划路径。
- **双判据降级控制器**：确定性判据（每步摊销 O(N) 重建次数，主判据）+ 墙钟 p99 保险丝（连续 2 窗口去抖，仅兜真实慢环境）。墙钟永不进主判据——实测机器负载抖动会让同 seed 结果不可复现。
- **失败原因分类**：全部失败有明确归因（撞墙/撞自身/撞障碍/被困/饥饿/超步数上限），不做模糊处理。
- **可复现性 CI**（.github/workflows/ci.yml）：push / PR 自动跑 typecheck（strict，含 scripts/）+ 构建 + 性质基 10⁴ + 故障注入 40 局 + 影子断言 8 局 + b-主专项 + 动态基准 20 局回归门（同 seed 确定性判据，CI 缩减局数与本地验收同源；大样本用 §七 完整命令本地复现）。README 徽章在仓库推送后点亮。

## 六、扩展实验与诚实结论

1. **单格障碍的 Warnsdorff 回搜**：实装限预算搜索（Warnsdorff 启发式 + 回溯 + 连通性剪枝）。实测结论：随机单格障碍布局的可行性预检通过率极低（黑白平衡 + 无死胡同 + 偶数格三条件在 15×15 场景 100 seeds 中无一同时满足），可行布局解出率 40–100% 但单次 0.4–0.8s。结论：安全 A* 仍是该场景主路线，Warnsdorff 只宜作残局收尾。
2. **静态上界推导的诚实尝试**：实装三种静态割族上界（单刀割 / 2×2 块割 / 不相交坏区域塔），均未在 medium-cell 布局上得到非平凡下界——本场景障碍生成规则已排除死胡同与孤岛，剩余布局黑白平衡且连通。残余损失来自蛇身动态围出的过程性口袋（依赖轨迹而非布局结构），「将其升级为逐图可计算上界」列为开放问题。
3. **宏格环邻接探针**：949 对共享边 / 0 对角相触——宏格对齐布局下圈合并条件恒成立（语义边界：仅佐证宏格结构友好，不代表一般 2-factor 分解）。
2. **回路构造对比**：随机 Prim 生成树回路的「捷径机会密度」0.29/格，显著高于 zigzag 的 0.18/格（+60%）——生成树缝合的绕块结构天然制造可跳跃段。
3. **捷径优化的诚实结论**：实装并 A/B 了三项优化（越食捷径、终局裕量收窄、路径食物计数），隔离矩阵显示收益 ≤1%——动态场景的步数由「回路遍历 + 事件绕行」主导，**margin 维度无 5% 优化空间**。该否定性结论连同数据一并保留（实验开关默认关闭），后续优化应转向事件调度与回路形态的联合设计。
