# 验证语义

本项目把声明分为三层，避免用实验数字替代证明。

## 1. 推导层

静态回路步和满足安全裕量的捷径步保持蛇身单调弧。推导只覆盖明确写出的前置条件，不自动扩展到任意障碍图或任意动态对手。

## 2. 运行时验证层

动态回路采用“候选 → 验证 → 提交”：

1. 在新数组中构造 `cells / idx / next / prev`；
2. 检查格子范围、唯一性、网格邻接和首尾闭合；
3. 检查蛇身在候选回路上仍为单调弧；
4. 成功后一次性替换正式状态。

`verifyStructure` 还会检查：

- 所有链接格恰好构成一个环；
- `next` 与 `prev` 双向一致；
- `cells[idx[cell]] === cell`；
- `next[cell]` 与下一个序号一致；
- 可选的期望支持集与回路支持集逐格相等。

影子校验器不复用动态维护状态。它从当前 `blocked + reserved` 视图重算参考回路，分别验证热路径支持集、单环、蛇身单调弧和参考回路可构造性。

哈密顿回路可能不唯一。canonical 归一化只能消除同一环的起点和方向差异，不能把两条不同的合法环变成同一序列，因此精确序列分歧不作为失败门。

## 3. 实验层

固定 seed 可以复现随机事件序列和逻辑结果，不能让墙钟耗时跨机器逐位一致。动态基准因此输出两类结果：

- 正确性：通关、明确失败原因、安全事故、结构错误、事件漏斗；
- 性能：pooled p50/p99、最差逐局 p99、峰值和超预算比例。

CI 使用 `--correctness-only`，仍打印耗时，但不会让共享 runner 的负载抖动阻断正确性检查。正式性能对比应记录 CPU、Node.js 版本、操作系统、命令、seed 范围与冷/热启动条件。

## 指标边界

| 指标 | 能说明什么 | 不能说明什么 |
|---|---|---|
| `win` | 蛇长达到当时自由格数 | 达到初始棋盘容量 |
| 初始容量比例 | 最终长度相对开局自由格数 | 未提供结构损失证书时的 C 性质 |
| 到期快照可达 | TTL 到期时静态快照中存在路径 | 能在期限内安全吃到、最终不饿死 |
| V 覆盖率 | 当前自由格中有多少曾被访问 | 同时占满或存在哈密顿回路 |
| pooled p99 | 所有采样决策的总体分位数 | 硬实时最坏时延 |

## 动态事件漏斗

调度器公开以下计数：`sampledCandidates`、`environmentRejects`、`fairnessRejects`、`strategyRejects`、`reservations`、`committedEvents`、`landRollbacks`、`unblockRetries` 和 `unblockAbandons`。

这使 A2-like 场景的限制可被直接观察：只要 `strategyRejects > 0`，它就不能被描述为严格“公平候选必须落地”。
