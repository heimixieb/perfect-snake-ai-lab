# Perfect Snake AI Lab（融合版）

[![reproducible-ci](https://github.com/heimixieb/perfect-snake-ai-lab/actions/workflows/ci.yml/badge.svg)](https://github.com/heimixieb/perfect-snake-ai-lab/actions/workflows/ci.yml)

本仓库是三份「贪吃蛇完美通关 AI」作业的融合版：以 5.1 B 为基座，吸收 5.1 A 与 3.1 的有效设计。

## 一句话目标

> **每个发布出去的数字都能被一条命令复现，每个"做不到"都说明它为什么是结构性的。**

「数字可复现」不只是声明：`.github/workflows/ci.yml` 在每次 push / PR 时自动跑类型检查、构建、性质基测试、故障注入、影子断言与动态基准门（CI 用缩减局数做回归门，验收口径与本地同源同 seed；发布数字用下表的完整命令复现）。徽章随每次 push 自动更新。

## 三条核心复现命令

```bash
npm install && npm run build                  # 构建（产物 dist/index.html 单文件）
npx tsx scripts/bench.ts all 10 1000          # 静态场景基准（5 场景 × 5 算法）
npx tsx scripts/bench-dyn.ts 100 7000         # 极限动态场景验收（100 局）
npx tsx scripts/property-test.ts 10000 42     # 性质基随机测试（10⁴ 操作）
npx tsx scripts/shadow-test.ts 8 9000         # 影子 refinement 测试（四层断言，自适应频率）
npx tsx scripts/fault-test.ts 40 8000         # 故障注入测试（含覆盖度指标 + 检测分支活性探针）
npx tsx scripts/twofactor-test.ts 50 7000     # b-主 2-factor 引擎验收（正确性+对照+统计）
npx tsx scripts/bench-dyn.ts 100 7000 --a2    # A2 对手档大样本验收（事件必须落地）
npx tsx scripts/a2-matrix.ts 100 7000         # A2 档压力矩阵（8 组合 × 100 局）
```

耗时随机器波动；**步数、通关率、不变量断言结果逐位可复现**（全部判据为确定性操作计数，墙钟只作保险丝不进判据）。

## 动态障碍场景（extreme-dyn）：真实基线

**场景参数**：30×30，2×2 宏格对齐障碍（初始密度 8%），每 40 步最多 2 块宏格动态增删，出现前 15 步预约位预告，5 个食物同时存在且有效期 80 步，每步决策预算 2ms。

**⚠️ 基线口径声明（重要）**：本项目的动态事件经历过一次关键修复——早期版本的预约格在重建时被错误缝回回路，导致**障碍实际从未真正阻断蛇的路径**（游戏退化为静态场景）。该状态下测得的数字（p99 0.69ms / 平均 47415 步）已作废，不在此引用。修复后障碍**真实落地并阻断路径**，以下为事件生效状态的首个完整基线：

| 指标 | 值 | 说明 |
|---|---|---|
| 通关率 | **100%**（100 局，seed 7000–7099） | 目标 ≥90% |
| 吃满率 | 100% | 蛇长 = 当时自由格数 |
| 单步 p99 | **1.23 ms** | 目标 ≤2ms；余量约 38% |
| 超预算步数 | 0.042% | 降级安全优先接住，零自撞 |
| 平均总步数 | 50366 | 事件绕行是步数大头 |
| 降级触发 | 33/100 局（全部墙钟保险丝） | 降级后仍 100% 通关 |

复现：`npx tsx scripts/bench-dyn.ts 100 7000`。耗时数值随机器波动，步数与通关率逐位一致。

### 压力矩阵（8 组合，各 6 局）

预告期 5/15 × 变动数 2/4 × 密度 0.08/0.12：**7 组 100% 通关**；唯一 83% 组合为「长预告(15) + 高频变动(4) + 低密度(0.08)」。所有组合失败模式均为优雅降级（放弃个别事件），无死锁、无非法状态——**崩溃边界已标定**。

### A2 档压力矩阵（8 组合 × 100 局，事件必须落地）

与 A1 矩阵同轴同值，但换用 A2 对手档（forceLand：候选不可拒、可落蛇头正前方），每组合 **100 局**（A1 矩阵为各 6 局，此档为发布前大样本标定）。结果：**8/8 组合 100% 通关**，全部 800 局合法终态 + 结构完好 + 零死锁；落地事件总计 **429,450 次**（对手真实触碰 grid），落地后回滚放弃 0 次；全矩阵 p99 峰值 1.54ms（预算 2ms），超预算步数最重组合 0.262%。**崩溃边界：未触及**（通关率在已测轴上无降级组合）。

复现：`npx tsx scripts/a2-matrix.ts 100 7000`。逐组合明细含 C 完成率、p50/p99/峰、失败原因分布（当前全空）与落地事件计数。

### 规模-耗时（扩展性曲线：30 → 50 → 100）

回应「你这能扩展吗」：同一引擎、零改动，把地图从验收尺寸 30×30 放大到 100×100（**11.1× 面积、900 → 10000 格**），实测两条曲线。全部档位通关 100%。

| 指标（p50） | 30×30（900 格） | 50×50（2500 格） | 100×100（10000 格） | 判读 |
|---|---|---|---|---|
| **O(1) 决策步进 · 静态** | 0.0047 ms | 0.0047 ms | 0.0049 ms | **与规模无关** ✓ |
| O(1) 决策步进 · 动态 | 0.0054 ms | 0.0054 ms | 0.0054 ms* | **与规模无关** ✓ |
| O(N) 构造（生成树回路） | 0.31 ms | 0.49 ms | 2.19 ms | 11.1× 面积仅 7.05×，**次线性** |
| O(N) 事件重建 · 动态 | 0.16 ms | 0.46 ms | 3.63 ms* | 单次重建全图一趟，**线性可见** |
| 静态档决策 p99 | 0.017 ms | 0.017 ms | 0.017 ms | 与规模无关 ✓ |

\* 动态 100×100 单局长跑样本（约 700 万步/局），p50 受调度器摊销口径影响，以 30/50 曲线为主要证据；重建 p99 上界 = 构造 p99 量级（约 3ms）。

复现：`npx tsx scripts/scale-test.ts`（30/50/100 全档；100×100 动态单局约 40 分钟）。**结论**：决策步进只看蛇头邻域与食物回路序（O(1)），实测从 900 格到 10000 格耗时纹丝不动；事件重建按 N 线性是理论必然、实测次线性（分配/JIT 常数在小图被高估）——扩展瓶颈明确落在重建，而重建恰是 O(N) 可证正确的手术。

## 边界与局限（每个"做不到"都是结构性的）

| 局限 | 为什么是结构性的 | 什么场景下成立 |
|---|---|---|
| 单格障碍图吃满率实测 77–93%（30 局均值 79%），未达 100% | NP-完备（Itai–Papadimitriou–Szwarcfiter 1982）+ 实测归因：本场景障碍生成规则已排除死胡同与孤岛（静态图黑白平衡、连通），静态割族上界（单刀割/2×2 块割/区域塔）均无非平凡下界——**残余损失来自蛇身动态围出的过程性口袋**，依赖蛇身轨迹而非布局固有结构。全局最坏情形（含死胡同的任意布局）下 NP-完备与死胡同论证仍成立 | 本场景布局类（规则 A 已排除死胡同）。含死胡同的任意布局有更强的结构性论证 |
| 奇×奇地图无哈密顿回路 | 网格图是二分图，回路长度必为偶数；奇×奇格数为奇 | 已用「缺角别名回路」解决：跳过角格并赋别名序号，实测 100% 覆盖 |
| 动态障碍需宏格对齐 | 单格变动无法用环缝合维护（§8.5.1 直连折叠不可行引理）；O(N) 全量重建只支持宏格对齐布局 | 单格动态障碍场景（extreme-dyn-B）未实装；Warnsdorff 回搜实测可行性窗口极窄，安全 A* 为主路线 |
| 强化学习不适用 | 同题权威开源实现实测 DQN 50% vs 图搜索 94%（**引用第三方、不同地图不同规则，非本项目 A/B 结果**，仅作路线判断依据） | 任何需要通关保证的场景 |

## 正确性论证（推导 / 验证 / 实测三层）

- **推导层**：沿回路步与捷径步的不变量由构造保持（I2 蛇身单调弧、I3 捷径安全裕量 gap−rel≥margin），证明骨架见应用内报告 §8.5；
- **验证层**：重建步的排序语义**不靠推导、靠验证**——`verifyStructure`（单环/2-正则/网格相邻/覆盖四项检查，完备性证明见报告）+ `monoArcChecker` 显式重建不变量；另配**影子 refinement 测试**（独立重算回路，canonical 归一化后逐位比对；断言频率自适应：**事件落地后 1 步必断言**——重建提交后的下一步是拓扑最脆弱时刻——+ 平时每 50 步稳定点，100 局终检 146661 次断言 0 失败）；
- **实测层**：性质基随机测试 10⁴ 操作、故障注入 246 万次事件（5 类注入全过）、100 seeds 基准——这三个数字支撑但不替代前两层。

关键引理：**直连折叠不可行**——2×2 宏格被环穿越的段，其两端外侧格在 4-邻接下必不相邻（穷举 12 种组合枚举 + 传送边实测），因此 O(1) 缝合不可行，O(N) 全量重建是唯一可证明正确的维护手术。

## 融合版的增量（相对三份原始作业）

1. **时间感知追尾判定**（来自 5.1 A）：终局兜底加入 `virtualSafe`，解决盘满局面静态 BFS 误杀；
2. **回路可行性预诊断**（来自 5.1 A）：偶数格/黑白平衡/死胡同 O(N) 预检；
3. **动态障碍场景 + hamilton-dyn 策略**（本迭代新增）：预约位、双判据降级、O(N) 重建、割色平衡上界、影子 refinement——见上文动态基线一节；
4. **手动控制模式**（来自 3.1）：方向键/WASD，不参与自动基准；
5. **扩展实验**（报告 §8.4.2/§8.5.2/§8.5.3）：捷径优化三变体 A/B（margin 维度已饱和的否定性结论）、Warnsdorff 可行性窗口（现实布局三条件难同时满足）、构造对比（随机 Prim 回路捷径机会密度 0.29/格 vs zigzag 0.18/格）、宏格环邻接探针（949 对共享边 / 0 对角相触——仅佐证宏格结构友好，不代表一般 2-factor 分解）。
6. **S/C/N/V 定义重写 + A2 对手档**（§8.5.2）：胜利判据从单一 fillRate 升级为四性质——S 安全无条件、C 完成锚定 initial_freeCount、N 不饿死按分量连通性、V 覆盖取 visited∩当前自由集；对手分级 A0 静态（100%）→ A1 预告不落蛇身（100%）→ **A2 事件必须落地、可落蛇头正前方（100 局大样本 100% 通关，C 完成率 99.8%）**→ A3 无预告不存在必胜策略（失败须附对手强制证书）。bench-dyn 新旧口径并列输出，N 违反计数（10 局 4517 次）暴露真实过程性损失。
7. **2-factor + 圈合并增量维护引擎**（`src/engine/twofactor.ts`，b-主）：维护对象从「单环」升级为「支持集上的 2-factor」（Dinic 二分图流求解 b-matching：S→黑 cap2 / 边 cap1 / 白→T cap2），圈合并用平行边 2-switch（两圈断边交叉重连）+ 对角 reroute（首跳强制交替路）兜底，宏格事件走亏格森林增广修复（O(受影响区域)——实测成功增广 99.7% 长度 ≤15、BFS 访问中位 3 格）。提交视图与 DynamicCycle 逐字段兼容，降级链 = 增量修复 → 生成树 O(N) 兜底 → 拒绝事件（不劣于经典引擎）。**A/B 实测（100 局 seed 7000–7099）**：通关 100%、单步 p99 0.11ms（经典 1.13ms，事件开销 ~10×↓）、超预算 0.002%（经典 0.016%）；正确性 2434 校验点全过、与生成树法全量重建逐事件判定一致（400/400）。`npx tsx scripts/bench-dyn.ts 100 7000 --twofactor` 复现（默认关闭，经典路径零改动）。
8. **验收基建补强**：fault-test 覆盖度指标两级输出——逐注入项分支计数 + 调度器事件结局空间（落地/预约拒绝/落地回滚/缝回放弃 4/4 全触发）+ **5 类违例检测分支计数**（传送边/第二环/prev 不一致/覆盖缺失/序号错乱）与**检测分支活性探针**（合成破损证明每类可检出，真实运行 0 触发 = 真零而非检测失效）；bench-dyn 支持 `--a2`（A2 档大样本）与 `--shadow`（影子终检，自适应断言频率）；`scripts/a2-matrix.ts` 为 A2 档 8 组合压力矩阵。

## 目录结构

```
├── src/engine/          引擎（无 DOM 依赖，Node / 浏览器通用）
│   ├── game.ts            蛇状态机（环形缓冲 + 位图，initialFreeCount / N 检查）
│   ├── grid.ts            网格与障碍生成（宏格对齐 / 单格 + 割容量）
│   ├── hamilton.ts        哈密顿回路构造（zigzag / 缺角别名 / 宏格生成树 + 起点遍历重试）
│   ├── dyn.ts             动态障碍维护（重建调度 / 公平性三条件 / 双判据降级控制器）
│   ├── strategies.ts      策略（hamilton / hybrid / hamilton-dyn / safe-astar / manual）
│   ├── search.ts          BFS / A* / 最长路径 / 时间感知追尾
│   ├── shadow.ts          朴素影子校验（refinement 四层断言用）
│   ├── twofactor.ts       2-factor 增量维护引擎（流求解 / 2-switch / reroute / 亏格增广）
│   ├── upperbound.ts      逐图结构性上界（不相交坏区域塔证书）
│   └── warnsdorff.ts      一般图哈密顿回搜（Warnsdorff + 连通性剪枝，限预算）
├── src/components/      UI（实时演示 / 基准测试 / 研究报告 三页）
├── scripts/             验收脚本（见「三条核心复现命令」）
└── dist/index.html      构建产物（单文件，可直接浏览器打开）
```

应用内置「研究报告」页含完整算法选型、数据结构、决策流程、量化对比、失效分析与证明骨架的展开版本。
